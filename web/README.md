# Интерфейс (`web/`)

React 18 + TypeScript + Vite + MUI — базовый пользовательский путь аналитика
ВКД поверх расчётного API S1-07 (`src/api/`, см. корневой `README.md` и
`contracts/README.md`). Правила фронтенда — `.ai/frontend-prompt.md`.

Путь: выбрать режим → задать окно и условия операции → рассчитать → изучить
воздействия → сравнить окна → изменить план → открыть доказательства →
просмотреть сохранённый результат. Сравнение окон здесь — это то, что
фактически возвращает API текущей версии сервиса: для `mode=current`
`space_weather` (FN-38) несёт реальный статус классификации наблюдения GOES
(`ok`/`missing_data`/`stale_data`/`source_error`/`beyond_horizon`), а `mmod`
(FN-39) несёт реальный статус нормировки к спорадическому фону NASA MEO
(`ok`/`missing_data`) — когда оба покрыты без критического пробела, окна
реально сравниваются правилом предпочтения окон (main-prompt.md §11);
критический пробел любого из двух по-прежнему честно исключает окно из
автоматического сравнения, интерфейс показывает это как есть, а не
имитирует готовую оценку. Экспорт (HTML/PDF) и полноценная историческая
аналитика — этап 2.

## Установка и запуск

```bash
npm install
npm run dev
```

Дев-сервер проксирует `/api` на `http://127.0.0.1:8000` (см.
`vite.config.ts`) — backend поднимается отдельно (корневой `README.md`,
раздел «Запуск»). Без запущенного backend работает вкладка «Демо-фикстуры»
(готовые примеры формы ответа) и форма расчёта (запросы завершатся ошибкой
сети, что тоже показывается как понятная ошибка, а не тихо).

## Проверки

Те же команды перед сдачей работы (`.ai/frontend-prompt.md`):

```bash
npm run lint          # ESLint по *.ts/*.tsx
npm run format:check  # Prettier
npm run build         # tsc -b (типы) + production-сборка Vite
npm test              # Vitest: src/utils/time.ts + тест гонки запросов
```

## Время и часовые пояса

Единственный формат отображения — UTC, с подписью, какое это время
(измерение/публикация/получение/отсечение/расчёт). Все преобразования — в
`src/utils/time.ts`; компонентам запрещено вызывать `Date` напрямую или
форматировать через `toLocaleString()`/`toString()` (подставляют таймзону
машины показа). Поле формы `datetime-local` трактуется как UTC «как есть»,
без подстановки локальной таймзоны браузера.

## Демонстрационный режим

Вкладка «Демо-фикстуры» показывает все четыре фикстуры контракта
(`success`/`incomplete`/`source-error`/`equal-windows`) через тот же
`ResultView`, что и живой расчёт — с явной пометкой «ДЕМО (фикстура)».
После подключения реального расчёта эта пометка не переносится на живые
результаты: `mode=current` через реальный API возвращает настоящие
орбитальные данные (CelesTrak) и честные статусы `not_implemented`/
`missing_data`/`source_error` там, где механизмы или источники ещё не
готовы — без слова «демо».
