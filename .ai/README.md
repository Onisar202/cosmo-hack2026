# Правила проекта для агентов (`.ai/`)

Набор правил для работы с ИИ над кейсом КосмоХакатона 2026 «Прогнозирование внешних рисков и планирование ВКД на МКС». Их читают участники команды со своими ассистентами, облачные routine «jira» и «PR fixer», а также Codex при ревью PR.

## Состав

| Файл | Кто и когда читает |
| --- | --- |
| [`agent-prompt.md`](agent-prompt.md) | Точка входа. Любая работа в репозитории начинается отсюда |
| [`main-prompt.md`](main-prompt.md) | Обязательные правила (§1–§10), предметные решения кейса (§11), требования постановки и критерии оценки (§12) |
| [`backend-prompt.md`](backend-prompt.md) | Работа над `sources/`, `store/`, `domain/`, `api/`, `export/` |

## Где что решено

- **Как писать код** — §1–§10 `main-prompt.md`.
- **Что делает сервис** — §11 `main-prompt.md`: два механизма воздействия, пороги, оценка окна, правило предпочтения, периоды, зоны ответственности, порядок отказа при нехватке времени.
- **Что проверяет жюри** — §12 `main-prompt.md`: обязательные требования постановки и критерии Т1–Т8, О1–О7.

Эти разделы самодостаточны: агенту, который видит только репозиторий, не нужны внешние документы, чтобы понимать кейс.

## Главное правило проекта

Цена молчаливой ошибки здесь — **правдоподобный неверный вывод о безопасности работ**, а её носитель — время: запись, попавшая в прогноз из прошлого позже момента отсечения, и `datetime` без таймзоны. Такой код не падает и проходит демонстрацию. Поэтому §1 `main-prompt.md` — самое строгое правило проекта.
