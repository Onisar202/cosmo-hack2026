# Правила фронтенда (`web/`)

Каталог: `web/`. Стек: React 18, TypeScript, Vite, MUI.

Читается вместе с [`.ai/main-prompt.md`](main-prompt.md). Пользовательские требования — §12 main-prompt (обязательные требования и критерии О4, О5); правило предпочтения окон, которое интерфейс показывает, — §11.

Минимальный пользовательский путь, который жюри проходит сам: выбрать режим → задать окно и условия операции → рассчитать → изучить воздействия → сравнить окна → изменить план → открыть доказательства → сохранить и выгрузить результат.

## Команды

- **`npm run lint`** — ESLint по `*.ts`, `*.tsx`.
- **`npm run format`** / **`npm run format:check`** — Prettier.
- **`npm run build`** — production-сборка.

Перед передачей работы: `npm run lint && npm run format:check && npm run build`.

## ESLint и Prettier

- `prettier` идёт последним в `extends`, чтобы отключить конфликты с форматированием.
- Неиспользуемое ловит TypeScript (`noUnusedLocals`, `noUnusedParameters`), правила `no-unused-vars` отключены.
- `react-hooks/exhaustive-deps` — `warn`, не блокирует сборку; исправлять осознанно.
- Не править стиль вручную в обход Prettier.

## Время и часовые пояса — критичный раздел

Ошибка здесь не ломает сборку: она тихо показывает неверное время в интерфейсе и в отчёте, который уйдёт жюри.

1. **Основной формат отображения — UTC.** Локальное время допускается только как явно подписанное дополнение рядом, никогда вместо.
2. **Запрещено форматировать даты через `toLocaleString()` без явной таймзоны** и через `new Date(...).toString()`. Браузер подставит таймзону машины, и на демонстрации с чужого ноутбука время разъедется.
3. **Все операции с датами — через один модуль `src/utils/time.ts`.** Он экспортирует парсинг ISO-строк из API, форматирование в UTC, форматирование давности («получено 42 минуты назад») и разбор длительностей. Прямые вызовы конструктора `Date` в компонентах не допускаются.
4. **Времена из API приходят строками ISO 8601 и хранятся строками** до момента отображения. Промежуточное преобразование в `Date` и обратно теряет смещение.
5. **Каждое показанное время подписано, какое оно:** измерение, интервал действия, публикация, получение или момент отсечения. Подпись «12:40 UTC» без указания, что это за время, бесполезна: в этом проекте на одном экране их до пяти.

## Состояния данных — не два, а больше

Интерфейс обязан различать состояния, которые легко слить в одно и тем самым соврать:

| Состояние | Как не должно выглядеть |
| --- | --- |
| Воздействие не выявлено | Так же, как «нет данных» |
| Данные устарели | Как актуальные, но с мелкой серой подписью |
| Оценить невозможно | Как «спокойно» или как пустое место |
| Интервал за горизонтом прогноза | Как спокойный участок диаграммы |
| Окно выведено из сравнения по неполноте данных | Как проигравшее окно |

- **Компонент, принимающий `value: number | null`, обязан принимать и причину отсутствия.** `null` без причины на экране превращается в прочерк, который читается как «ничего не происходит».
- **Отсутствие данных не рисуется нулём на графике.** Разрыв линии, а не точка на оси.
- **Реконструкция исторической геометрии помечается визуально** и не выглядит как проверенный прогноз.

## Формулировки

- **Текст объяснений приходит из расчёта.** Интерфейс не дописывает уверенности, не добавляет физических последствий и не обобщает уровень словами, которых нет в ответе API.
- **Запрещены подписи вида «безопасно», «риска нет», «можно выходить».** Сервис оценивает внешние показатели, а не допуск к реальной ВКД. Допустимые формулировки — о наблюдаемых величинах и их пересечении с окном.
- **Сокращение длительности ВКД показывается как изменение плана,** а не как улучшение обстановки. Это отдельная визуальная пометка, а не просто новые числа.
- **Наблюдение, внешний прогноз и расчёт команды различаются** формой, а не только цветом: цвет теряется при печати отчёта и на проекторе.

## Работа с API

- **Ответы нескольких запросов не смешиваются.** При быстрой смене параметров пользователем результат устаревшего запроса отбрасывается (`AbortController` или сверка идентификатора запроса), а не дорисовывается поверх нового.
- **Старая рекомендация не остаётся под новыми параметрами.** Смена любого поля формы либо запускает пересчёт, либо явно помечает показанный результат как относящийся к прежнему запросу.
- **Каждый экран проверяется на всех четырёх фикстурах** из `contracts/`: успешный расчёт, неполные данные, ошибка источника, равнозначные окна. Проверка только на успешном ответе не считается проверкой.
- **До появления реального API интерфейс строится на этих фикстурах** и помечает данные как демонстрационные. Пометка снимается при подключении реального расчёта.

## Стиль кода в диффах

- Соответствовать существующим паттернам в `src/` (именование, структура страниц, MUI).
- Не раздувать объём правок: без рефакторинга «заодно» несвязанных файлов.
- После правок — снова `npm run lint`, при необходимости `npm run format`.
