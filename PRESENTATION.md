# Задача выбора окна

- Пользователь задаёт режим, начало, длительность и период поиска
- Сервис сравнивает минимум два окна одинаковой длительности
- Для каждого окна оцениваются космическая погода и метеороидная среда
- Результат содержит предпочтение, компромисс или явную недостаточность данных

**Цель:** объяснить различия между окнами, не выдавая неполные данные за безопасность

# Два независимых механизма

| Космическая погода                             | Метеороидная составляющая MMOD                      |
| ---------------------------------------------- | --------------------------------------------------- |
| Поток протонов GOES и прогнозные сообщения     | Прогноз NASA MEO для низкой околоземной орбиты      |
| Классификация уровня воздействия на интервал   | `ratio_to_background` для интервала                 |
| Наблюдение, внешний прогноз и расчёт разделены | Траектория связывает среду с положением станции     |
| Непокрытый горизонт остаётся неполнотой        | Результат не трактуется как вероятность повреждения |

Механизмы не складываются в необоснованный общий risk score.

# Прогноз из прошлого

1. Пользователь фиксирует момент `as_of` до начала обоих окон
2. Расчёт получает только записи с `published_at <= as_of`
3. Версии источников и покрытие замораживаются в snapshot
4. Более поздние наблюдения используются только для проверки прогноза
5. Архивный пробел остаётся `INSUFFICIENT_DATA`

Минимальный прогнозный горизонт составляет 6 часов. Период поиска может достигать 24 часов.

<!--

# Правило сравнения окон

- Предпочтение: одно окно не хуже по всем сопоставимым показателям и лучше хотя бы по одному
- Компромисс: разные механизмы предпочитают разные окна
- Недостаточно данных: покрытия не хватает для обоснованного выбора
- `source_agreement`: `CONSISTENT`, `CONFLICT` или `INSUFFICIENT_DATA` внутри одного механизма

Конфликт источников и конфликт физических факторов показываются отдельно.

<!--

# Устройство сервиса

1. Коннекторы получают и нормализуют данные
2. Неизменяемое хранилище сохраняет оригиналы, версии и результаты
3. Доменные модули рассчитывают орбиту и оценки механизмов
4. Сервис сравнивает окна и формирует доказательства решения
5. React-интерфейс и JSON/HTML export читают один сохранённый результат

FastAPI, Pydantic, SQLite, SGP4, React, TypeScript, Docker Compose

# Демонстрация сервиса

1. Открываем публичный URL
2. Выбираем `historical_forecast` и задаём `as_of`
3. Сравниваем окна A и B
4. Открываем оценки Space Weather и MMOD
5. Показываем coverage, публикацию и ограничения
6. Открываем сохранённый result и JSON/HTML export
7. Показываем experiment summary и baseline

Целевое время screencast: 2,5–3 минуты.
